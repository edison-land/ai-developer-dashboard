# 额外需求 Backlog（计划外增强）

> 本文件记录 `docs/spec.md` 之外的、计划外新增需求，供后续排期。每条需求给出**动机 / 范围 / 数据模型影响 / API 影响 / UI 影响 / 待定决策点**。落地前需把"待定决策点"逐条敲定，再把已确认的条款回写进 `spec.md` 相应章节（User Stories / 数据模型 / HTTP API / 进度表）。术语与类型沿用 `spec.md`：`UnifiedProject`、`sources: SourceId[]`（`'claude-code' | 'codex' | 'git'`）、`lastActiveMs`、`recencyBucket`（`'active-now' | 'today' | 'stale'`）、`Stage`。

## R1 · Agent（来源）筛选

**动机**：用户同时用 Claude Code 和 Codex，有时只想看"我在 Codex 上跑过的项目"或"只用过 CC 的项目"，快速聚焦某一工具的工作面。

**范围**
- 在「晨间分流」与「阶段看板」顶部加一个**筛选栏**，含**来源多选**：`Claude Code` / `Codex` / `Git`（对应 `project.sources`）。
- "agent"在本项目语境 ≈ AI 工具来源（CC / Codex）；git 是机械信号来源，严格说不是 agent。见下方待定①。

**数据模型影响**：无。`project.sources` 已存在，纯前端筛选。

**API 影响**：无强制；可选 `GET /api/projects?sources=claude-code,codex` 做服务端预筛（默认不传 = 全部）。

**UI 影响**
- 筛选栏组件（与 R2 共用）。
- 来源 chip 可复用现有「来源徽标」的视觉。

**已定决策**（2026-07-27）
- ① UI 标签写"来源筛选"，**列出全部三个**（CC / Codex / Git）。
- ② 多选语义 = **OR**（具备任一选中来源即命中）。
- ③ 筛选状态**跨刷新持久化**（localStorage 或 settings 表 `ui_filters` key）。

---

## R2 · 最后活跃时间筛选

**动机**：项目越积越多，需要按"多久没动过"快速收窄，例如"只看本周内活跃的"，把久未触碰的暂时隐去。

**范围**
- 筛选栏加一个**活跃时间**选择，基于 `lastActiveMs`。预设档（与现有 `recencyBucket` 对齐并更细）：
  - 全部 / 今天（≤1 天）/ 本周（≤7 天）/ 本月（≤30 天）/ 更早（>30 天）。
- 与 R1 的来源筛选可叠加（AND）。

**数据模型影响**：无。`lastActiveMs` 已存在。

**API 影响**：无强制；若服务端预筛可加 `?activeWithinDays=7`。

**UI 影响**：与 R1 同一筛选栏的一个下拉 / 按钮组。

**已定决策**（2026-07-27）
- ① 用**预设档**（全部 / 今天 / 本周 / 本月 / 更早），不做自由滑块。
- ② 不做"隐藏 N 天未活跃"快捷开关——与 R3 归档区分：时间筛选是临时视图，归档是持久状态。

## R3 · 归档功能

**动机**：有些项目已彻底搁置 / 完成，不该每天占据看板视线，但又不舍得删；需要一个"眼不见"的归档区，随时能找回并恢复。

**范围**
- 任一项目卡可**归档**：归档后从「晨间分流 / 阶段看板 / 活动」全部隐藏。
- 头部一个**「查看归档」按钮** → 打开归档列表（抽屉 / 模态 / 单独视图），列出已归档项目，每条带**「恢复」**动作。
- 恢复后项目回到正常看板。

**数据模型影响**（新增一张表，仿 `stage_overrides` 的 per-path 模式）
```sql
CREATE TABLE archives (
  canonical_path TEXT PRIMARY KEY,
  archived_at_ms INTEGER NOT NULL
);
```
- 归档是**对 canonical path 的持久状态**，独立于机械信号（适配器每次重跑不会改变它）。

**API 影响**（沿 `:enc` base64url 约定扩展）
| 方法 + 路径 | 作用 |
|---|---|
| `GET /api/projects` | 默认**排除**归档项（行为变更，需向后兼容说明） |
| `GET /api/projects?includeArchived=true` | 含归档项（归档视图用） |
| `POST /api/projects/:enc/archive` | 归档（upsert `archives`） |
| `DELETE /api/projects/:enc/archive` | 恢复（删 `archives` 行） |
- 或新增 `GET /api/archived` 专用端点（二选一，见待定③）。

**UI 影响**
- 卡片溢出菜单 / 按钮加「归档」。
- 顶部「查看归档」按钮 → 归档列表（建议抽屉，避免新增一级路由）。
- 归档列表项 = 紧凑卡 + 「恢复」按钮 + 归档时间。

**已定决策**（2026-07-27）
- ① **粘性**：归档后即便产生新活跃也不自动解除，只能手动恢复。
- ② 对"很久没动"的项目**只提示、不自动归档**。
- ③ 复用 `/api/projects?includeArchived=true`，**不新建** `/api/archived`。
- ④ 归档项**同时从「活动」时间线隐藏**。

## R4 · 阶段看板 hover 展开（紧凑 ↔ 完整）

**动机**：阶段看板默认信息密度高、列窄，平时只扫基本面；想深看某列时，不必点进单项目深视图，直接把鼠标移到那一列即可"放大"看全貌。

**范围**（纯前端交互，`KanbanView` 内）
- **默认态**：每列只显示项目**基本信息**——名称、来源徽标、`recencyBucket`、`lastActionOneLiner`（截断）、阶段标记。
- **hover 态**：鼠标进入某一列（"分类的框"）→ 该列**悬浮抬升、变宽**（elevation + 加宽 + 阴影），列内每张卡**展开为完整状态**——加上 `synth.summary` / `nextStep` / `blockers`、git 详情（分支 / 脏文件 / ahead-behind / 最近提交）、`lastActiveMs` 等。
- 鼠标移出 → 平滑回到默认态。

**数据模型影响**：无。

**API 影响**：无。完整状态所需字段大部分已在 `GET /api/projects`；`synth` 详情随 Phase 3 落地后可用（当前可先用机械字段展开，synth 字段渐进填充）。

**UI / 实现要点**
- **抬升方式**：用 `transform: scale()` + `z-index` + `box-shadow` 做**覆盖式弹出**（不挤占邻居、不触发整页 reflow），而非改 `width` 推开邻居（会抖动）。**强烈倾向覆盖式。**
- **动画**：`transform` / `opacity`（GPU 友好），~150–200ms ease，避免 layout thrash。
- **边界列**：最左 / 最右列弹出方向需内缩（`transform-origin` 朝内侧），防止溢出视口。

**已定决策**（2026-07-27）
- ① 加宽到**固定目标宽度**（不整列等比放大，文本换行更可控）。
- ② **不考虑触屏 / 键盘**，hover 是唯一触发方式（本项目单用户、桌面本地应用）。
- ③ 同屏**只允许一列展开**，hover 到 B 列时 A 列自动收回。
- ④ 展开列两侧留**轻量半透明遮罩** + 高亮当前列。

## 汇总：影响一览

| 需求 | 数据模型 | API | UI | 纯前端? |
|---|---|---|---|---|
| R1 来源筛选 | 无 | 可选查询参数 | 筛选栏 | ✅ 基本纯前端 |
| R2 时间筛选 | 无 | 可选查询参数 | 筛选栏 | ✅ 基本纯前端 |
| R3 归档 | 新表 `archives` | 新端点 + `?includeArchived` | 卡片菜单 + 归档抽屉 | ❌ 需后端 |
| R4 看板 hover 展开 | 无 | 无 | `KanbanView` 交互 | ✅ 纯前端 |

**共享件**：R1 + R2 共用一个顶部「筛选栏」组件，状态可持久化（settings `ui_filters` 或 localStorage）。

## 建议落地顺序与 Phase 映射

1. **R4**（看板 hover 展开）——纯前端打磨，挂在 Phase 4 的 `KanbanView` 上即可，最快见效。
2. **R1 + R2**（筛选栏）——纯前端 + 一个共享组件，可并入 Phase 5 打磨批。
3. **R3**（归档）——唯一需动后端（新表 + 端点 + `/api/projects` 默认排除归档的行为变更），单列为一个小 Phase（如 Phase 4.5 / 5.5），独立交付。

> 顺序仅为建议；R1/R2/R4 互相独立，可任意调整。
