# 桌面产品化设计

> 状态：✅ 高层设计已批准
> 批准日期：2026-08-01
> 适用里程碑：v1.0.0、v1.1.0、v1.2.0

## 设计目标

把现有“CLI 启动后在浏览器使用”的入口，逐步迁移成可独立交付的 Windows 软件。桌面化只改变进入产品和交付产品的方式，不改变现有页面、展示内容和业务逻辑。

## 总体路线

采用“薄壳渐进式”路线：复用现有 `packages/core`、`packages/server` 和 `packages/ui`，通过薄桌面外壳依次解决入口、安装和外部测试交付。

| 版本 | 解决的问题 | 主要交付物 | 目标使用者 |
|---|---|---|---|
| v1.0.0 | 不再依赖 CLI 和浏览器入口 | Windows 免安装测试版 | 项目所有者 |
| v1.1.0 | 可以长期安装、升级和卸载 | Windows 安装包 | 项目所有者 |
| v1.2.0 | 可以交给不参与开发的人测试 | 首位外部测试者交付包 | 首位外部测试者 |

## 共同边界

- Windows 优先、本地单用户。
- 页面结构、展示内容、交互行为和业务逻辑保持不变。
- 软件自动管理本地后端和内部地址，不让使用者处理终端或端口。
- 现有项目状态、归档、今日重点、AI 总结缓存和模型配置必须连续保留。
- CLI 不再面向普通用户，仅暂时作为内部开发、测试和诊断工具。
- 关闭桌面窗口即完全退出；不做托盘、开机启动或后台常驻。
- 不做云同步、多用户、自动上传日志和自动更新。

## 阶段关系

1. v1.0.0 先证明“独立软件入口”成立，不同时承担安装和外部发布。
2. v1.1.0 在 v1.0.0 验收后，补齐安装、升级、卸载和数据保留。
3. v1.2.0 在 v1.1.0 验收后，补齐真实机器验证、使用说明和首位外部测试者交付。

每个阶段完成后先更新对应 `completion.md`，再进入下一阶段。

## 已排除路线

- 不把入口迁移、安装和外部交付塞进同一个里程碑。
- 不重写原生桌面界面。
- 不借桌面化增加新的业务功能或改版现有页面。
- 不把 v1.2.0 定义为正式公开发布。
