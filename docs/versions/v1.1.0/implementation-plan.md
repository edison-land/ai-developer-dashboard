# v1.1.0 实施计划：安装与数据管理

> 执行日期：2026-08-01
> 前置条件：v1.0.0 免安装桌面版已通过审核；v1.1.0 需求已批准实施。

## 目标

在不改变页面、展示内容、交互行为或 `packages/core`、`packages/server`、`packages/ui` 业务逻辑的前提下，把 v1.0.0 portable 版变成可以安装、覆盖升级、卸载和重装的 Windows 软件，并保证现有个人数据可继续使用。

## 技术边界

- 继续使用 Electron 薄壳和现有本地 server；保持原 `appId`，让同一软件的安装包可以识别覆盖升级。
- 新增 Windows NSIS 安装包，创建开始菜单和桌面快捷方式；不加入自动更新、云同步、多用户、日志上传或公开发布流程。
- 安装版数据目录使用 Electron 的用户数据目录下的 `data` 子目录，不放在安装目录内；卸载器显式不删除用户数据。
- 首次运行安装版时，如果新的数据目录还不存在而旧 `~/.ai-dashboard` 存在，则通过临时目录完成复制，并在新目录保留带时间戳的迁移备份和清单。旧目录不删除，迁移失败时不损坏源数据。
- 已设置 `AI_DASHBOARD_DATA_DIR` 时继续使用该兼容覆盖路径，供 CLI、开发和诊断使用；这条路径不自动迁移，避免改变现有测试和诊断语义。
- 迁移只在桌面层处理；server 继续接收 `resolveConfig({ dataDir })`，页面和核心数据模型不变。

## 实施切片

1. 增加可测试的数据目录解析与迁移模块：区分显式兼容路径、安装版路径和旧 CLI/portable 路径；采用 staging、备份和清单保证可恢复。
2. 接入 Electron 主进程：在启动本地 server 前完成数据目录准备，沿用现有单实例、随机回环端口和退出清理流程；启动失败显示可理解原因。
3. 将 desktop package 从 portable 目标扩展为版本化 NSIS 安装包，保留相同 `appId`、创建开始菜单/桌面入口，并显式保留卸载后的用户数据。
4. 增加迁移单元测试、安装包结构检查和 Windows 真实验证脚本，覆盖首次安装、旧数据接续、覆盖升级、卸载保留、重装恢复、迁移备份和恢复证据。
5. 运行全仓测试、类型检查、UI 哈希回归、安装包构建和实际 Windows 流程；以 v1.1.0 `requirements.md` 逐条自审。

## 验证门槛

- 安装包为 Windows x64 NSIS `.exe`，版本号为 v1.1.0，能创建常用启动入口。
- 页面资源与 v1.0.0 构建输入保持一致；现有 core/server/ui 自动化测试不回归。
- 旧 CLI 和 v1.0 portable 的默认数据能在安装版首次启动时被自动承接，阶段、归档、今日重点、总结缓存和模型配置在数据库中保持不变。
- 同一安装包再次运行后，数据和安装入口仍可用；卸载后用户数据目录和迁移备份仍存在；重新安装后能继续读取相同数据。
- 迁移中断或失败不会删除旧数据，并能根据备份清单恢复；不把代码签名或公开发布作为完成条件。
- 严格自审的 Standards 与 Spec 两个轴均无阻断项；若有阻断，继续修复、重测和复审。

## 明确不做

- 不修改现有页面、展示内容、交互流程、core/server/ui 业务能力。
- 不实现自动更新、云同步、多用户、自动上传日志、公开发布或大规模 Windows 兼容承诺。
- 不提交、不推送、不归档工作区改动。
