# v0.1.0 需求：机械核心

> 阶段目标：先建立不依赖 AI 的本地项目工作台基础。

## 用户问题

用户同时推进许多项目，每天需要逐个打开 Claude Code 和 Git 仓库，才能知道哪些项目最近活跃、是否仍在运行、工作区是否干净。

## 需求范围

### 1. 本地数据采集

- 从 Claude Code 本地记录读取项目、最近动作、最后活跃时间和 busy/idle 状态。
- 从 Git 读取分支、最近提交、脏文件数、ahead/behind 和 upstream 状态。
- 非 Git 目录、无 upstream 和空仓库不能导致整个采集失败。

### 2. 项目合并

- 使用规范化后的 Windows 路径作为项目身份。
- 统一正反斜杠、盘符大小写、尾部斜杠和 `\\?\` 长路径前缀。
- 中文、空格和大小写差异必须正确处理。
- 同一路径的不同来源合并成一张项目卡。
- 最近活跃时间取所有来源中的最新值。

### 3. 本地应用基础

- 使用 pnpm monorepo 分开核心逻辑、服务端、网页和启动入口。
- 提供健康检查、项目列表、机械刷新、阶段覆盖和设置接口。
- 提供基础项目卡、阶段看板、设置页和错误提示。
- `pnpm start` 可以启动本地服务并打开浏览器。

### 4. 本地存储与安全

- 使用本机 SQLite 保存设置和人工阶段覆盖。
- 项目采集数据不上传云端。
- 不读取 Codex 密钥、Claude 密钥或大型日志数据库。
- 服务错误需要返回可理解的原因，页面提供重试。

## 架构边界

| 模块 | 责任 |
|---|---|
| `packages/core` | 领域模型、路径规则、适配器、聚合和本地存储 |
| `packages/server` | Hono 本地接口与静态网页托管 |
| `packages/ui` | React + Tailwind 网页 |
| `apps/cli` | 启动服务并打开浏览器 |

核心模块不依赖 React 或 HTTP，以便未来被 Electron 复用。

## 验收标准

1. 能采集真实 Claude Code 项目并附加 Git 状态。
2. 中文路径和非 Git 目录不会破坏全量列表。
3. busy 项目进入“正在进行”，近期项目进入“今天”，其余进入“需要关注”。
4. 接口错误能区分网络、HTTP 和解析问题。
5. 自动测试、类型检查和网页构建通过。

## 本版本不做

- Codex 数据源；
- AI 项目总结；
- 完整活动时间线；
- 归档与高级筛选；
- Electron 安装包。
