# v0.9.1 需求：交互效率与模型接口通用化

> 状态：✅ 已完成
> 记录日期：2026-07-29  
> 阶段目标：减少整理项目和调整今日重点所需的点击，让最近做过的项目更容易回到视野，并把模型接入改成可复用的通用配置。

## 用户结果

完成本阶段后，用户可以：

- 直接拖动阶段卡片完成分类；
- 在首页优先看到最近做过的项目；
- 鼠标移到首页重点卡片上时立即调整重点；
- 从页面右上角进入历史归档；
- 筛选动态列表；
- 通过统一的模型接口配置不同服务商。

## 1. 阶段看板拖动分类

### 需求

- 阶段看板中的项目卡片可以拖到“想法、开发中、待验证、完成、搁置”任一列。
- 放下卡片就等同于手动修改项目阶段，不需要再打开项目详情。
- 拖动时要清楚显示卡片可以放到哪一列，以及放下后的目标阶段。
- 修改成功后立即更新看板，并保存结果；刷新页面后分类不能恢复原状。
- 修改失败时，卡片回到原位置，并给出明确提示。
- 用户仍可在项目详情中取消手动分类，恢复由系统自动判断阶段。

### 验收

1. 卡片可以跨阶段列拖动，目标列会显示接收提示。
2. 放下后阶段立即改变，刷新页面后结果保持。
3. 手动分类标记与现有阶段覆盖规则一致。
4. 请求失败时不会出现“界面已移动、实际未保存”的假成功。

## 2. 首页推荐考虑最近改动时间

### 需求

- 首页三张推荐卡片的自动选择必须明确考虑项目的最近活动或改动时间。
- 用户手动固定的项目仍然优先保留。
- 在自动推荐项目中，最近做过的项目通常应比长期未动的项目更靠前；最近时间不能只在其他条件完全相同时才生效。
- “正在运行”和“需要用户立即处理”仍属于重要信号，可以因紧急性优先于单纯的最近改动。
- 推荐理由要与实际排序一致，避免卡片被时间因素选中却显示无关理由。

### 验收

1. 没有手动固定时，近期有活动的普通项目能够进入前三张推荐。
2. 长期未活动的项目不会仅因旧状态长期占据推荐位。
3. 手动固定、正在运行、需要处理和最近改动之间的顺序有稳定测试。
4. 相同数据多次刷新得到相同顺序。

## 3. 首页卡片悬浮调整重点

### 需求

- 在桌面端，鼠标悬浮到重点卡片时直接显示常用调整操作。
- 至少支持：固定或取消固定、向前或向后调整位置、今天不再推荐。
- 操作区不能妨碍用户点击卡片进入项目详情，也不能因为按钮出现造成卡片明显跳动。
- 键盘聚焦卡片时也能看到并使用相同操作。
- 触摸设备没有悬浮状态，因此继续保留可点击的“调整重点”入口或等价操作。

### 验收

1. 鼠标移入卡片即可调整，不必先打开单独面板。
2. 各操作执行后，三张卡片的顺序和状态立即同步。
3. 鼠标、键盘和触摸设备都有可用入口。

## 4. 历史归档入口移到全局右上角

### 需求

- “历史归档”入口放在页面右上角，紧邻“总结全部”。
- 用户在首页、项目列表、阶段看板和动态页都能从同一位置进入归档。
- 原项目列表工具栏中的旧入口移除，避免同一功能出现两个不同位置。
- 归档列表、恢复项目等现有能力保持不变。

### 验收

1. 各主要页面都能看到右上角的历史归档入口。
2. 入口位于“总结全部”旁边，点击后进入现有归档界面。
3. 旧入口不再重复出现，归档和恢复功能没有回归。

## 5. 动态列表加入筛选

### 需求

- 动态页提供清楚、可组合的筛选控件。
- 首批筛选维度包括：
  - 来源：Claude Code、Codex、Git；
  - 项目；
  - 时间范围：今天、最近 7 天、全部。
- 用户可以一键清除全部筛选。
- 筛选后没有结果时要显示空状态，并说明当前是被筛选条件限制，而不是数据读取失败。

### 验收

1. 单个筛选条件和多个条件组合都能正确缩小动态列表。
2. 清除筛选后恢复完整列表。
3. 刷新动态数据时保留当前筛选条件。
4. 空结果与加载失败显示不同提示。

## 6. 通用模型接口与提供商预设

### 需求

- 模型调用统一采用当前已有的 OpenAI 兼容 Chat Completions 规范。
- 设置页统一为四项核心配置：
  - 模型提供商预设；
  - 请求地址；
  - API Key；
  - 模型名称。
- “模型提供商”只用于帮助用户自动填写请求地址和推荐模型，不作为限制接口能力的开关。
- 用户选择预设后仍可修改请求地址和模型名称，并可选择“自定义”填写其他兼容服务。
- 首批常用预设包括：
  - 智谱 AI；
  - OpenAI；
  - DeepSeek；
  - 月之暗面 / Kimi；
  - 硅基流动；
  - OpenRouter；
  - 自定义。
- 现有智谱配置必须平滑保留，升级后不要求用户重新填写已经保存的 Key。
- API Key 仍只保存在本机，接口和日志不得返回明文。

### 验收

1. 选择任一预设会填入正确请求地址，用户仍能手动修改。
2. 自定义请求地址、API Key 和模型名称可以保存并完成一次模型总结。
3. 现有智谱用户升级后可以继续使用原配置。
4. 设置接口只返回“是否已配置”，不返回 API Key。
5. 不支持通用规范的服务商不会被误标为可直接使用。

## 跨功能验收

1. 新增交互在亮色和暗色主题下均可识别。
2. 关键状态变化有自动化测试，并完成一次真实浏览器人工检查。
3. 不破坏现有的阶段覆盖、今日重点、归档恢复、动态刷新和 AI 总结流程。

## 本版本不做

- 同一阶段列内的自定义卡片排序；
- 为每家模型厂商开发独立的专有协议适配器；
- Electron 桌面安装包，仍属于暂缓的 v1.0.0；
- 拖动任务后自动开启或继续对话，仍属于 v2.0.0。
