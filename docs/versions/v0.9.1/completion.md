## 维护修复记录（2026-07-31）

- 状态：✅ 已修复。
- 原因：Codex 数据库中的最新线程时间正确，但读取适配器把 `config.toml` 的无时间项目种子覆盖了真实线程信号，项目卡因此回退显示较旧的 Claude Code 时间。
- 修复：线程信号优先；只有没有线程记录时才使用项目种子，并新增重叠场景回归测试。
- 结果：真实 `ai-developer-dashboard` 项目重新显示当前 Codex 活动时间，并归入“最近活跃”。

## 实际完成

- 阶段看板支持拖动到想法、开发中、待验证、完成、搁置五列；放下后先即时更新，接口失败会退回原列并提示，成功后通过现有阶段覆盖接口持久化。未分类列仍可作为拖动来源，详情页的“清除阶段”规则保持不变。
- 首页自动推荐把最近活动时间作为独立排序层，同时保留手动固定、正在运行和需要处理的优先级；相同输入有稳定的路径排序。重点卡片的调整区在桌面悬停和键盘聚焦时出现，触摸设备继续使用“调整重点”。
- “历史归档”已移到全局顶栏，紧邻“总结全部”；项目工具栏旧入口已移除，归档抽屉和恢复能力未改动。
- 动态页支持来源、项目、今天/最近 7 天/全部时间的组合筛选、一键清除和本地保存。服务端与页面端都使用同一套筛选规则，空结果和读取失败使用不同提示。
- 模型设置统一为提供商预设、请求地址、API Key、模型名称。已加入智谱 AI、OpenAI、DeepSeek、月之暗面/Kimi、硅基流动、OpenRouter、自定义预设，并通过一个 OpenAI 兼容 Chat Completions 适配器调用；地址和模型仍可编辑。

## 兼容与数据迁移

- 原有 `zhipuApiKey`、智谱模型和配置字段继续可读；设置页保存时同时兼容旧智谱密钥字段，不要求用户重新填写。
- 设置接口只返回 `hasApiKey` 及历史兼容的布尔状态，不返回任何明文密钥；密钥按提供商保存在本机 SQLite 设置表。
- Anthropic 预留项明确标记为不同协议并拒绝保存/调用，不把它误标为 OpenAI 兼容服务。
