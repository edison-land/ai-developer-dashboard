# v0.6.0 需求：聚焦式界面重设计

> 阶段目标：用户打开页面后三秒内知道今天最值得推进的三个项目。

完整决策见 [设计文档](design.md)，详细步骤见 [实施计划](implementation-plan.md)。

## 信息架构

主导航固定为：

1. **今日**：三个重点、少量状态摘要和随后关注；
2. **项目**：搜索、筛选、列表/阶段切换和项目管理；
3. **动态**：跨来源最近动作；
4. **设置**：模型、密钥、刷新和主题。

默认页面不再让所有项目获得相同视觉重量。

## 今日重点

- 固定最多三个重点项目。
- 用户可以置顶、调整顺序或仅在当天移除。
- 不足三个时由规则自动补位。
- 运行中和需要用户处理的项目优先。
- 归档、完成和当天移除项目不进入候选。
- 没有 AI 摘要时使用最近动作降级，不显示空白卡。

## 项目页

- 搜索项目名、路径和当前情况。
- 保留来源、时间筛选。
- 支持列表视图和紧凑阶段视图。
- 点击项目查看完整详情。
- 项目详情集中阶段、总结、下一步、阻塞、Git 状态和归档操作。

## 视觉系统

- 提供暖白浅色和深墨深色主题，并支持跟随系统。
- React 启动前读取主题，避免错误主题闪烁。
- 导航和操作使用统一图标，不再使用彩色 Emoji。
- 主要验收尺寸为 1366×768。
- 页面不得产生整页横向溢出。

## 数据与模块

- 推荐规则放在 `packages/core` 纯函数中。
- 重点偏好由服务端 SQLite 持久化。
- 主题保存在浏览器，确保首屏渲染前即可读取。
- 归档时同步清理该项目的重点偏好。

## 验收标准

1. 首屏能看到状态摘要和三张重点卡。
2. 推荐、置顶、排序、当天移除有自动测试。
3. 项目管理操作仍可从详情中完成。
4. 明暗主题的关键页面均完成视觉检查。
5. 建立一个统一验收命令，执行类型检查、测试和构建。

## 本版本不做

- 修改底层数据采集架构；
- 新增云服务；
- Electron；
- 触屏和完整键盘交互适配；
- 恢复阶段列 hover 放大。
