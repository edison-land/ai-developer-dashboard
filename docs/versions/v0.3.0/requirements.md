# v0.3.0 需求：AI 总结与成本控制

> 阶段目标：让系统按需解释项目状态，同时保证输入、成本和失败范围可控。

## 用户结果

用户可以为单个项目或全部项目生成：

- 五阶段判断；
- 一句话当前情况；
- 可执行的下一步；
- 阻塞项；
- 后续版本使用的“需要用户处理 / 等待中”关注类型。

## 输入边界

AI 输入必须是有界 bundle：

- 最近用户动作，截断到有限字符；
- Claude Code JSONL 尾部少量记录，只读文件尾，不读全文；
- Git 最近提交、分支、ahead/behind 和最多 20 行状态；
- 每个字段硬截断，目标约 1.8k token。

## 输出与缓存

- 使用 zod 校验阶段、摘要、下一步和阻塞项。
- 允许从 Markdown 围栏或包裹文字中提取 JSON。
- 输入哈希未变化时直接返回缓存，不调用模型。
- 模型失败时返回旧缓存或清楚的错误，页面不能崩溃。
- 密钥保存在本机数据库，接口只返回“是否已配置”。

## 模型范围

- 核心使用 `SynthProvider` 抽象隔离模型厂商。
- 当前先接通用户已有 Key 的智谱 BigModel。
- 默认使用非推理 `glm-4-flash-250414`。
- Anthropic 和 OpenAI 只保留接口位置，本版本不承诺可用。

## 触发方式

- 单项目“生成总结”按钮。
- “总结全部”批量接口。
- 不在每一轮流式对话后自动调用模型。

## 验收标准

1. 合法输出能通过 schema，异常输出被拒绝。
2. 病态长输入仍被截断。
3. 同输入第二次调用命中缓存且不调用 provider。
4. provider 报错不会破坏项目列表。
5. API Key 不出现在设置响应或日志中。
6. 真实模型冒烟可以从本机设置读取 Key，不经过命令行。

## 本版本不做

- Anthropic/OpenAI 的实际 provider；
- 自动刷新时触发 AI；
- 批量任务的逐项页面进度；
- 云端密钥托管。
