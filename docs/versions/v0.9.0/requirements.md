# v0.9.0 需求：UI 回归保护

> 状态：✅ 已完成
> 阶段目标：为已经稳定的主要工作流建立自动化保护，避免界面调整悄悄破坏功能。

## 前置条件

v0.8.0 已完成，页面设置与运行行为一致，真实模型冒烟流程可重复。

## 1. 最小 UI 测试基础

- 为 `packages/ui` 建立 Vitest + React Testing Library 或等价的轻量环境。
- 测试关注用户能看到和操作的行为，不绑定内部组件实现。
- 模型、网络和本地数据使用固定 fixture，不调用真实 API。

## 2. 四条关键流程

### 今日重点

- 自动生成最多三个重点；
- 人工置顶与顺序；
- 当天移除；
- 归档项目不出现。

### 项目查找

- 搜索；
- 来源 OR 筛选；
- 时间筛选；
- 列表/阶段切换持久化。

### 项目管理

- 打开和关闭详情；
- 阶段覆盖与恢复自动；
- 归档、查看归档、恢复。

### 批量总结

- 显示 X/总数；
- 收到事件后更新对应项目；
- 单项失败后继续；
- 最终统计正确。

## 3. 启动与异常场景

- 首次启动、空项目、无 API Key；
- Claude Code 或 Codex 数据源不存在；
- 端口占用；
- 数据库升级；
- 服务端错误与响应格式异常。

## 4. 发布资料

- 编写用户故障排查。
- 建立固定发布检查表。
- 区分自动验证、真实模型验证和人工视觉验证。

## 完成标准

- 四条核心工作流有自动回归；
- `pnpm verify:ui-redesign` 或新的统一入口包含 UI 测试；
- 常见启动异常有明确处理和文档；
- 新用户只看根 README 和文档入口即可启动、验证、排错。

## 本版本不做

- 大规模重写 UI；
- 新增业务能力；
- Electron；
- 云端 CI 中调用真实模型。
