# v0.9.0 故障排查：网页与 CLI 阶段

> 归属：v0.9.0 · UI 回归保护
>
> 状态：历史阶段资料。它记录当时网页/CLI 入口的排错方法；后续 Windows 桌面版的打开、数据和交付问题请看[桌面版使用、调试与交付指南](../../desktop-usage-and-delivery.md)。

## 启动失败

### 端口已被占用

默认端口是 `7777`。启动命令会直接提示冲突端口；可以换一个端口：

```bash
pnpm start -- --port 7788
```

如果网页打开了旧端口，确认浏览器地址和终端打印的地址一致。

### 页面显示 UI 未构建

先构建网页，再启动服务：

```bash
pnpm build:ui
pnpm start
```

开发时也可以把后端和 Vite 前端分开运行，地址见根目录 `README.md`。

### 数据库升级或被锁定

应用会在本机数据目录自动执行缺失的表迁移。若提示 SQLite 被占用：

1. 先关闭另一个 AI Developer Dashboard 进程；
2. 等待正在进行的刷新完成；
3. 再重试刷新。

不要手动删除数据库；其中包含阶段覆盖、归档、重点偏好和模型缓存。

## 项目列表或来源为空

- Claude Code 不存在时，页面会显示来源不可用，但不会阻止其他来源展示。
- Codex 数据库不存在或 schema 变化时，Codex 会降级，Git 项目仍可显示。
- Git-only 项目以 Git 最近提交时间作为活跃度兜底。
- 没有项目时，先在 Claude Code 或 Codex 中打开一个项目，再点击“刷新”。

## AI 总结失败

### 没有 API Key

进入“设置”，配置已实现的智谱 BigModel Key。Key 只保存在本机，不会在设置响应中回显。

### provider 不可用

当前只有 `zhipu` provider 可以作为活动选择。Anthropic 和 OpenAI 只作为未来能力展示，不能保存为当前 provider。

### 刷新时 AI 失败

开启“刷新时一并更新 AI 总结”后，刷新会先保存新的机械项目状态，再逐项调用模型。模型失败会显示失败数量和错误，但不会回滚机械状态。输入没有变化时会命中缓存，不重复调用。

### 批量总结中断

批量总结按顺序逐项执行。单项失败会继续；浏览器或网络连接中断时，本次批次不会自动恢复，已收到的结果仍保留。

## 验证命令

提交前运行：

```bash
pnpm typecheck
pnpm test
pnpm build:ui
pnpm verify:ui-redesign
```

真实模型冒烟使用临时数据库和真实项目快照，不会污染正式缓存：

```bash
pnpm smoke:synth
```

它会在没有 Key、模型输出非法或输入超过 2500 token 时失败，并打印执行日期、provider、模型、项目数、token 和失败数；不会打印 Key 或完整对话。
