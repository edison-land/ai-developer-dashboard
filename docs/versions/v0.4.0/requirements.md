# v0.4.0 需求：阶段管理

> 阶段目标：把项目的机械状态与 AI 判断整理成可人工确认的五阶段工作流。

## 阶段模型

固定五个阶段：

| ID | 含义 |
|---|---|
| `idea` | 想法 |
| `building` | 开发中 |
| `verifying` | 待验证 |
| `done` | 完成 |
| `stalled` | 搁置 |

## 功能需求

1. 项目可以按五个阶段分组显示。
2. 有 AI 总结时使用 AI 阶段。
3. 用户可以手动覆盖阶段。
4. 用户可以清除覆盖，恢复自动判断。
5. 页面需要区分阶段来自人工还是 AI。
6. 没有 AI 结果时允许阶段为空，不伪造判断。

## 优先级规则

```text
人工覆盖 > 当前输入对应的 AI 缓存 > 未知
```

- 人工判断始终优先。
- 输入变化后，旧 AI 总结标记为 stale，但页面仍保持可用。
- 路径继续使用 `pathKey` 作为 SQLite 主键，避免同一项目产生多份覆盖。

## 接口

- `PATCH /api/projects/:enc/stage`：保存人工阶段。
- `DELETE /api/projects/:enc/stage`：清除人工阶段。
- 非法阶段返回 400。
- 不存在的项目返回 404。

## 验收标准

1. 五个阶段能稳定展示。
2. 人工覆盖能够跨刷新保存。
3. 人工覆盖高于 AI 阶段。
4. 清除后恢复 AI 阶段或未知。
5. 非法值不会写入数据库。
