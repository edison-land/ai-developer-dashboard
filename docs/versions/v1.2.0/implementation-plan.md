# v1.2.0 实施计划：首位外部测试者交付

> 执行日期：2026-08-01
> 前置条件：v1.1.0 安装、覆盖升级、卸载、重装和数据保留已通过总控独立审核。

## 目标

在不改变现有页面、展示内容、交互行为或 `packages/core`、`packages/server`、`packages/ui` 业务逻辑的前提下，把现有 v1.1.0 Windows x64 安装包整理成首位不参与开发者可以独立尝试的交付包。

本阶段的“版本号”有两个层次：

- **交付里程碑**：v1.2.0，表示首位外部测试者交付准备阶段。
- **安装包软件版本**：1.1.0，表示实际使用的已验证 NSIS 安装包；不重新伪装成 1.2.0，也不改变安装包内部版本号。

## 技术与产品边界

- 复用 `dist/v1.1.0/AI-Developer-Dashboard-v1.1.0-setup-x64.exe`，不重做安装器，不生成公开发布版本。
- 仅新增版本化交付说明、核对信息和验收记录；不改页面、展示内容、交互行为或核心业务逻辑。
- 不做自动更新、公开发布、云同步、多用户、自动上传日志或付费代码签名。
- 外部测试者只需要 Windows 安装包和说明，不需要仓库、CLI、Node.js、浏览器或端口配置。
- 反馈采用人工提供信息的方式；启动失败时不自动上传日志或项目数据。

## 实施切片

1. **锁定交付物**：核对安装包文件名、Windows x64 属性、ProductVersion、文件大小和 SHA-256；排除 v1.0 portable 与 v1.1.1 覆盖升级测试包。
2. **编写测试者说明**：提供安装、启动、卸载、数据保留、迁移备份恢复、已知限制、启动失败处理和反馈模板。
3. **本机真实验证**：使用现有 `scripts/verify-desktop-installer.ps1 -KeepArtifacts` 在 Windows 本机的临时安装目录、临时用户数据和隔离 fixture 中验证首次安装、启动、旧数据接续、快捷方式、覆盖升级、卸载保留、备份恢复和重装；保留脚本输出、启动日志、迁移清单和恢复数据库路径。该证据只代表项目所有者本机隔离验证，不代表首位外部测试者或另一台干净电脑。
4. **独立自审**：用 `requirements.md` 逐条核对交付物和证据；对 v1.2.0 文档变更运行 Standards/Spec 两轴 `code-review`，发现内部阻断时修复并重测。
5. **进度交接**：更新本文件、`completion.md` 和 `docs/README.md`，如实写明内部准备已完成、外部测试者尚未验收；不伪造外部结果。

## 验证门槛

- 只能识别并交付 ProductVersion 为 `1.1.0`、文件名为 `AI-Developer-Dashboard-v1.1.0-setup-x64.exe` 的 Windows x64 安装包；v1.2.0 只作为交付里程碑号。
- 测试者说明包含可复制的 SHA-256 核对命令和期望值。
- 说明包含简短安装、启动和卸载步骤，并说明默认卸载保留个人数据。
- 说明包含启动失败弹窗的处理、人工反馈入口和禁止上传的敏感信息边界。
- 真实 Windows 验证通过，且记录为“项目所有者本机隔离环境验证”，不称为外部测试者结果或独立干净电脑验收。
- 页面和业务内容只通过现有 v1.1.0 证据确认；不引入 v1.2.0 专属产品改动。
- `pnpm test`、`pnpm typecheck`、版本文档结构检查和 `git diff --check` 通过。

## 外部验收门槛

以下事项必须由首位不参与开发者的真实反馈补齐，不能由本阶段内部验证代替：

- 测试者是否根据说明识别了正确安装包；
- 测试者是否独立完成安装、启动、基本使用和卸载；
- 测试者是否遇到问题，以及反馈内容和后续修复项。

在取得这些证据并经总控最终审核前，v1.2.0 不能标记为最终完成。

## 明确不做

- 不修改 `apps/desktop`、`packages/core`、`packages/server` 或 `packages/ui` 的业务逻辑。
- 不把项目所有者本机验证写成首位外部测试者验证。
- 不把 v1.1.1 覆盖升级测试包作为外部交付物。
- 不提交、不推送、不归档，也不覆盖工作区已有的 README、市场研究、工具目录、截图和 v1.0/v1.1 未提交改动。
