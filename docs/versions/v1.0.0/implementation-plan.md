# v1.0.0 实施计划：桌面入口迁移

> 执行日期：2026-08-01
> 前置条件：`docs/desktop-productization.md` 与本版本需求已批准。

## 目标

在不修改现有页面和业务逻辑的前提下，增加一个 Windows 桌面薄壳，并生成可直接双击的免安装测试版。

## 技术边界

- 新增 `apps/desktop`，只负责桌面窗口、单实例和本地后端生命周期。
- 继续直接复用 `packages/server`、`packages/core` 与 `packages/ui`。
- 后端只监听 `127.0.0.1`，由操作系统自动分配可用端口；端口不暴露给普通用户。
- 继续使用现有 `resolveConfig()`，默认读取 `~/.ai-dashboard`、Claude Code 与 Codex 的现有数据。
- 渲染窗口不开放 Node.js 能力；不增加桌面专属业务接口。
- `apps/cli` 保留，定位为内部测试和诊断入口。

## 实施切片

1. 建立可测试的桌面生命周期控制器：先拿单实例锁，再启动后端和窗口；重复启动只唤醒已有窗口。
2. 让 server 支持由操作系统分配端口，并在真实监听后再向调用方报告地址。
3. 接入 Electron 主进程：加载现有 UI、使用安全窗口配置、启动失败时显示可理解错误。
4. 配置 Windows portable 打包：先构建 UI，再打包桌面主进程和原生 SQLite 依赖。
5. 增加自动化和真实运行验证：单实例、单后端、关闭退出、重启、现有数据路径、UI/API 可用、网页回归。

## 验证门槛

- 桌面生命周期与 server 端口测试通过。
- 全仓测试、类型检查和 UI 构建通过。
- 真实 portable `.exe` 可双击启动，并显示现有页面。
- 第二次启动不会形成第二套窗口或后端。
- 关闭窗口后主进程与监听端口消失，再次启动成功。
- 默认数据目录与现有 CLI 相同。
- 严格逐条核对 `requirements.md` 后给出明确的“通过”结论；不通过则继续修复和复审。

## 明确不做

- 不制作安装包，不处理升级、卸载或外部测试者交付。
- 不修改现有页面、交互流程或业务能力。
- 不加入托盘、后台常驻、开机启动、自动更新或云能力。
