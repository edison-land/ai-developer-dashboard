# v0.8.0 需求：现有能力名实一致

> 状态：✅ 已完成
> 阶段目标：先消除会误导用户的设置，再用真实环境证明当前网页版本可用。

## 1. 接通“刷新时一并总结”

- `synthOnRefresh` 保持默认关闭。
- 用户启用后，手动刷新和定时刷新完成机械采集，再更新未归档项目的 AI 总结。
- 机械刷新成功、AI 总结失败时，仍保留新的机械状态。
- AI 失败需要显示统计和错误，不能让整个刷新表现为失败。
- 使用内容哈希缓存，输入未变时不重复调用模型。
- 避免定时器重叠启动两轮批量总结。

## 2. 收紧模型提供商范围

- 设置页暂时只能启用已经实现的智谱 provider。
- Anthropic/OpenAI 可以显示为未来能力，但不能保存成当前活动 provider。
- 服务端继续拒绝未实现 provider，形成第二层保护。
- 接入新 provider 时必须同时提供实现、测试和真实冒烟，再开放选择。

## 3. 修正真实模型冒烟

- 输出实际使用的模型名，删除硬编码旧模型提示。
- 输入超过 2500 token 时判定失败，不只警告。
- 首次总结、schema、第二次缓存命中必须通过。
- 使用临时缓存数据库，不污染正式 dashboard cache。
- 记录执行日期、provider、model、选中项目数、token 和失败数量。
- 不打印 API Key 或完整 transcript。

## 4. 真实运行验收

至少检查：

1. `pnpm start` 正常启动；
2. Claude Code、Codex、Git 项目能采集；
3. 单项目总结成功；
4. 同输入第二次命中缓存；
5. “总结全部”逐项更新；
6. 自动总结开关的开/关行为一致；
7. 无 Key 和模型失败时页面可恢复。

## 自动测试

- 刷新开关关闭时不调用 AI。
- 开关开启时机械刷新后调用 AI。
- 归档项目不参与。
- AI 失败不回滚机械刷新。
- 未实现 provider 不能成为活动选择。
- smoke 的模型输出和失败阈值有测试或可重复检查。

## 完成标准

- 页面设置与实际行为完全一致；
- 现有 122 项测试继续通过，并新增本版本回归测试；
- 类型检查、UI 构建和统一验收通过；
- 真实模型冒烟有可追溯记录；
- 成本为零的批量进度 QA 完成人工浏览器检查。
