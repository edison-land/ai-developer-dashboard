# v0.7.0 需求：批量总结实时进度

> 阶段目标：点击“总结全部”后，每完成一个项目就立即看到结果，不再等待整批结束。

完整方案见 [设计文档](design.md)。

## 后端要求

- 仍由一个批量请求负责全部未归档项目。
- 项目按当前顺序逐个处理，模型最大并发为 1。
- 每完成一个项目立即回传一条 NDJSON 事件。
- 事件包含项目结果、状态和累计统计。
- 单项目失败不能中止后续项目。
- 全部结束后重新采集并回传最终统计。

## 页面要求

- 按钮执行中显示“已完成 X/总数”。
- 显示更新、缓存、失败数量。
- 当前完成的项目卡立即替换为最新结果。
- 不使用全页骨架屏，不引入新的醒目进度条。
- 结束后恢复“总结全部”并保留最终统计。

## 错误处理

- 单项目失败计入失败数量，批次继续。
- 流解析异常使本次操作失败并提示用户。
- 请求断开后不承诺自动恢复该批次。
- 最终项目重取失败时，保留已收到的逐项结果。

## 验收标准

1. 第二个项目未完成时已经可以读取第一个进度事件。
2. 缓存、更新和失败统计正确。
3. 归档项目不会进入批次。
4. stale 项目仍属于批量范围。
5. 同时最多处理一个项目。
6. 页面能逐项更新项目卡和进度文案。

## 本版本不做

- 后台任务队列；
- 断线恢复；
- 浏览器并行调用多个单项目接口；
- 真实模型视觉验收。
