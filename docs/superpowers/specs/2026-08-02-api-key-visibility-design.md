# API Key 可见性切换设计

> 状态：待用户审阅
>
> 日期：2026-08-02
>
> 范围：设置页 API Key 的标签、保存后回显和显示/掩码切换。

## 目标

让项目所有者在设置页保存 API Key 后，重新打开或刷新页面仍能看见完整 Key，并能用眼睛按钮在完整文本与掩码之间切换。

## 已确认的取舍

当前设置接口只返回“是否已设置”，以避免密钥出现在页面响应中。用户已明确选择改为本机明文回显：`GET /api/settings` 将返回当前提供商的 API Key。

这意味着任何能够访问本机设置页或查看其本机网络响应的人都可能读取该 Key。项目没有登录、多用户或远程访问入口；本次不新增这些能力。密钥仍只保存在本机 SQLite，且不得写入日志、错误提示、测试输出或文档示例。

## 交互

1. 字段标签固定为 **API Key**，不再包含提供商名称或“已设置”状态。
2. 初次打开、保存成功、刷新页面和再次进入设置页时，已保存的 Key 默认以完整文本显示。
3. 眼睛按钮放在输入框右侧：默认状态表示“隐藏 API Key”；点击后输入框显示掩码，按钮改为“显示 API Key”；再次点击恢复完整文本。
4. 用户正在输入的新 Key 时也遵循同一显示状态；保存按钮、提供商切换和既有保存逻辑保持原样。

## 组件与数据流

- `packages/server/src/app.ts`：设置读取响应新增当前提供商的 `apiKey` 明文字段；写入接口、SQLite 存储和现有提供商兼容规则不变。
- `packages/ui/src/views/SettingsView.tsx`：初始状态从设置响应载入 API Key；移除“保存后清空输入框”的行为；`SecretField` 改为固定标签和带眼睛按钮的可见性控件。
- `packages/ui/src/components/Icons.tsx`：仅在现有图标库缺少眼睛/闭眼图标时，补充这两个展示图标；不引入新依赖。

## 错误与边界

- 空 Key 继续保持空输入框，不显示“已设置”占位提示。
- 保存失败时保留输入内容和当前显示/掩码状态，便于重试。
- 切换提供商后，页面只显示当前提供商从接口取得的 Key；不在前端猜测或缓存其他提供商的密钥。
- 不修改桌面壳、CLI、数据迁移、模型调用或公开发布流程。

## 测试边界

1. **设置 API 边界**：读取已保存的当前提供商设置时，响应包含该 API Key；写入行为继续正确。
2. **设置页面边界**：加载后完整 Key 默认可见；点击“隐藏 API Key”后输入变为密码掩码；再次点击恢复可见；保存后不清空。

这些测试只断言接口响应和用户能看见、点击的控件，不依赖组件内部状态实现。

## 完成标准

- 标签显示为 `API Key`。
- 已保存 Key 在重新打开设置页后默认完整可见。
- 眼睛按钮可在明文与掩码间双向切换，并有可访问名称。
- 不在日志、错误提示、文档示例或自动测试输出中写入真实 Key。
- 相关服务端与 UI 测试通过，现有全量测试和类型检查通过。
