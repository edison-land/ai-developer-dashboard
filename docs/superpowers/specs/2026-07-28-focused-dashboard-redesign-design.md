# AI Developer Dashboard 聚焦式界面重设计

- 状态：已由用户逐段确认
- 日期：2026-07-28
- 范围：网页端信息架构、今日重点、项目浏览、双主题与相关本地偏好
- 目标：让用户打开页面后，三秒内知道今天最值得推进的三个项目

## 1. 背景与问题

现有系统的数据架构是清楚的：

1. `packages/core` 汇总 Claude Code、Codex 与 Git 的项目状态。
2. `packages/server` 将这些本地数据提供给网页。
3. `packages/ui` 用“晨间分流、阶段看板、动态、设置”四个页面展示数据。

问题主要出在信息展示层，而不是数据层：

- 默认页面一次铺开全部项目，29 个项目获得了接近相同的视觉重量。
- 单张项目卡同时展示路径、来源、阶段、最近动作、Git、AI 总结、下一步、阻塞与操作按钮。
- 蓝、绿、黄、紫、红和 Emoji 同时出现，颜色没有稳定分工。
- 用户虽然能看到很多信息，却不能快速判断“现在最应该做什么”。
- 阶段看板依靠整列悬停放大，容易造成视觉跳动和新的信息拥挤。

因此，本次重设计保留数据采集与业务能力，重新划分首页、项目管理和项目详情的职责。

## 2. 设计目标

### 2.1 核心目标

- 默认首页只回答一个问题：今天先推进哪三个项目。
- 普通笔记本首屏完整显示三个今日重点，不需要向下滚动才能看到第三个。
- 当前情况、下一步和推荐原因形成稳定的阅读顺序。
- 暖白与深墨两套主题都保持同样清楚的信息层级。
- 所有项目、阶段、Git 和管理操作仍然可达，但不再常驻首页。

### 2.2 非目标

- 不重写 Claude Code、Codex 或 Git 的采集逻辑。
- 不新增云端同步、多人协作或账号体系。
- 不让新的 AI 模型直接决定项目优先级。
- 不恢复阶段看板的悬停整列放大。
- 不把桌面本地工具扩展成移动端优先产品。
- 不在本次重设计中加入拖拽框架；重点顺序用明确的左移、右移操作完成。

## 3. 已确认的总体方向

| 决策 | 确认结果 |
|---|---|
| 首页首要答案 | 今天最应该推进什么 |
| 今日重点数量 | 固定三个 |
| 决策方式 | 系统推荐，用户拥有最终控制权 |
| 手动与自动关系 | 手动置顶保持，其余位置自动补足 |
| 首页布局 | 三张并列重点卡，下方少量紧凑项目 |
| 重点卡第一层内容 | 项目当前情况 |
| 重点卡第二层内容 | 下一步 |
| 主题 | 暖白编辑台与深墨专注台两套，可切换 |
| 首次主题 | 跟随 Windows 明暗设置 |
| 全部项目 | 独立“项目”页面，用列表/阶段切换 |
| 项目详情 | 点击后打开右侧详情面板 |
| 阶段看板详情交互 | 点击卡片打开详情，不再悬停放大 |

## 4. 信息架构

主导航保持四项，不增加认知负担：

1. **今日**：三个重点、状态摘要、少量最近变化。
2. **项目**：全部项目的列表和阶段视图、筛选、归档入口。
3. **动态**：跨 Claude Code、Codex 与 Git 的时间线。
4. **设置**：AI 提供商、刷新策略、主题跟随选项等。

导航不再使用彩色 Emoji。每项使用统一风格的小图标和文字；当前页面只用一种强调色标识。

### 4.1 全局头部

全局头部仅保留：

- 产品名称；
- 最近更新时间；
- 刷新操作；
- 暖白/深墨主题切换。

归档、筛选和阶段调整属于项目管理，不放在全局头部。

## 5. “今日”页面

### 5.1 页面顺序

从上到下固定为：

1. 轻量状态摘要；
2. “今天先做这 3 件事”标题与“调整重点”入口；
3. 三张并列重点卡；
4. 最多五条“最近变化/需要关注”紧凑项目；
5. “查看全部项目”入口。

状态摘要只显示三个可行动数字：

- 正在运行；
- 需要用户处理；
- 总项目数或本周活跃数。

状态摘要使用文字和小圆点，不使用三张大统计卡。

### 5.2 今日重点卡

每张卡的阅读顺序固定：

1. 顺序编号与阶段；
2. 项目名称；
3. **当前情况**：优先使用 `synth.summary`，最多两行；
4. **下一步**：优先使用 `synth.nextStep`，最多两行；
5. 推荐原因与最后活跃时间。

卡片不常驻显示以下信息：

- 完整路径；
- Claude Code/Codex/Git 来源徽标；
- Git 分支、未提交文件和提交信息；
- 模型名称与生成时间；
- 阶段下拉框；
- 总结、归档等操作按钮。

点击卡片打开项目详情面板。需要更新总结、调整阶段或归档时，在详情面板中完成。

### 5.3 AI 信息缺失时的降级

- 没有 AI 总结：用 `lastActionOneLiner` 作为“当前情况”。
- 没有下一步：显示“下一步待确认”，并在详情面板提供“生成总结”。
- 总结已过期：继续显示旧内容，同时用低强调文字标记“需要更新”。
- 总结请求失败：不清空已有内容，不让卡片变成错误框。

### 5.4 最近变化列表

该区域最多显示五条，且不重复今日重点：

1. 先显示“需要用户处理”的项目；
2. 再按最后活跃时间补足；
3. 每行只显示名称、阶段和最后活跃时间；
4. 点击任一行打开同一个项目详情面板。

## 6. 今日重点推荐规则

推荐是可解释的固定规则，不是一个不可见的 AI 分数。

### 6.1 用户偏好

偏好包含：

- `pinnedPaths`：有顺序的置顶项目，最多三个；
- `dismissed`：当天从自动推荐中移除的项目；
- 当前本地日期。

行为规则：

- 手动置顶一直保留，直到用户取消置顶。
- 用户当天移除的自动推荐，当天不再出现。
- 到本地时间第二天，昨日的移除记录自动失效。
- 置顶项目被归档或改为完成后，自动取消置顶。
- 恢复归档不会自动恢复原置顶状态。

### 6.2 自动补位顺序

去掉归档、完成、当天移除和已置顶项目后，按以下层级选择：

1. 当前存在运行中会话的项目；
2. 明确需要用户处理阻塞的项目；
3. 处于“开发中”或“待验证”且近期活跃的项目；
4. 其他最近活跃项目。

同一层级内依次按以下条件稳定排序：

1. `lastActiveMs` 从新到旧；
2. `canonicalPath` 字典序，作为完全相同时的稳定兜底。

自动卡片的推荐原因只能从固定集合中选择：

- 正在进行；
- 需要你处理；
- 近期活跃；
- 手动置顶。

界面不显示难以解释的综合分数或概率。

### 6.3 “需要用户处理”与“等待中”

为了避免把“等待接口限额恢复”误判成今日重点，现有总结结果增加一个可选字段：

```ts
type AttentionKind = "user-action" | "waiting" | "none" | "unknown";
```

- `user-action`：存在用户现在可以执行的动作，可提高自动优先级。
- `waiting`：主要在等待外部条件，不进入前两层自动推荐。
- `none`：没有特别阻塞。
- `unknown`：旧缓存、无总结或无法判断，只按机械信号排序。

该字段随用户原有的“生成总结”一起产生，不触发额外 AI 请求。旧缓存没有该字段时按 `unknown` 处理。

### 6.4 调整重点

点击“调整重点”后进入明确的编辑状态：

- 置顶或取消置顶；
- 左移或右移；
- 今天移除。

退出编辑状态后恢复干净的阅读卡片。正常状态不显示这些管理按钮。

## 7. “项目”页面

### 7.1 顶部工具栏

项目页顶部使用一条紧凑工具栏：

- 项目搜索；
- 来源筛选；
- 活跃时间筛选；
- “列表 / 阶段”视图切换；
- 归档入口。

来源和时间筛选使用下拉或弹出面板，不再把所有选项平铺成一长排彩色胶囊。

### 7.2 列表视图

列表是默认视图。每行只显示：

- 项目名称；
- 阶段；
- 一句当前情况；
- 最后活跃时间；
- 必要时一个低强调的“需要处理”标记。

点击一行打开项目详情面板。

### 7.3 阶段视图

阶段视图继续包含：

- 想法；
- 开发中；
- 待验证；
- 完成；
- 搁置；
- 未分类。

卡片只显示名称、最近情况和时间。点击卡片打开详情面板。

布局规则：

- 1440 像素及以上：六列并排；
- 1024–1439 像素：三列乘两行；
- 更窄宽度：单列或双列，不产生整页横向溢出。

不再渲染悬停浮层，也不把完整 `ProjectCard` 复制进看板列。

### 7.4 项目详情面板

右侧详情面板集中承载：

- 完整路径与来源；
- AI 当前情况、下一步、阻塞与更新时间；
- Git 分支、工作区状态、ahead/behind 与最近提交；
- 阶段修改；
- 更新总结；
- 归档。

面板宽度以 440–480 像素为目标，窄窗口时占满可用宽度。关闭面板后，用户仍停留在原列表或阶段位置。

## 8. 双主题视觉系统

两套主题共享同一组“颜色职责”，仅替换具体色值。

| 颜色职责 | 暖白编辑台 | 深墨专注台 |
|---|---|---|
| 页面背景 | `#F4F0E8` | `#07101F` |
| 普通表面 | `#FFFDF8` | `#0D192B` |
| 重点卡片 | `#FFFFFF` | `#122038` |
| 主要文字 | `#1C2430` | `#EEF4FF` |
| 次要文字 | `#697386` | `#8A97AD` |
| 边界 | `#D7D1C5` | `#263957` |
| 主要操作 | `#2457D6` | `#63D7FF` |
| 注意 | `#A96F12` | `#E1A84B` |
| 成功/运行 | `#12805C` | `#46C89A` |
| 失败 | `#C63D42` | `#F06B72` |

使用规则：

- 蓝色或青色只用于当前页面、主要操作与下一步。
- 琥珀色只用于需要注意或阻塞。
- 绿色只用于正在运行或成功。
- 红色只用于真实失败。
- 普通来源、路径、时间和模型信息不分配独立彩色。
- 正文对比度目标不低于 4.5:1。

字体以中文和数字快速扫读为目标。优先使用 Windows 自带的 `Bahnschrift` 表现英文、数字和编号，中文回退到清楚稳定的中文无衬线字体；不依赖在线字体服务。

### 8.1 主题状态

主题偏好有三个内部状态：

- `system`：跟随 Windows；
- `light`：暖白；
- `dark`：深墨。

首次为 `system`。头部按钮可直接在暖白和深墨之间切换；设置页提供“重新跟随 Windows”。手动选择保存在浏览器本地。

页面在 React 启动前读取主题偏好并设置 `data-theme`，避免启动时先闪出错误主题。

## 9. 模块边界

| 模块 | 单一职责 | 依赖 |
|---|---|---|
| `FocusSelector` | 从项目和偏好中稳定选出三个重点 | `UnifiedProject`、本地日期、偏好 |
| `FocusPreferenceStore` | 保存置顶顺序和当天移除 | 本地 SQLite |
| `TodayView` | 组织状态摘要、重点卡和最近变化 | 项目数据、重点选择结果 |
| `FocusCard` | 展示当前情况、下一步与原因 | 单个重点项目 |
| `ProjectsView` | 管理列表/阶段切换与筛选 | 项目数据、筛选状态 |
| `ProjectDetailsDrawer` | 展示完整详情和管理操作 | 单个项目、现有 hooks |
| `ThemeController` | 解析 system/light/dark 并设置页面主题 | `localStorage`、Windows 主题 |

推荐算法放在 `packages/core` 的纯函数中，方便独立测试；页面组件不自己拼装排序规则。服务端只负责持久化偏好，避免把界面状态塞进项目采集器。

## 10. 数据与接口

新增本地表：

```sql
CREATE TABLE focus_preferences (
  canonical_path TEXT PRIMARY KEY,
  pinned_rank INTEGER CHECK (pinned_rank IN (0, 1, 2)),
  dismissed_on TEXT,
  updated_at_ms INTEGER NOT NULL,
  UNIQUE (pinned_rank)
);
```

约束：

- `pinned_rank` 只能为 0、1、2 或 `NULL`；
- 同一排名只能对应一个项目；
- `dismissed_on` 使用本机日历日期 `YYYY-MM-DD`；
- 写入置顶顺序时使用一个事务，避免中途出现重复排名。

新增接口：

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/focus-preferences` | 读取置顶顺序与当天移除 |
| `PUT` | `/api/focus-preferences` | 原子更新有顺序的置顶和当天移除 |

`PUT` 请求形状：

```ts
{
  pinnedPaths: string[]; // 唯一、有序、最多三个
  dismissedPaths: string[]; // 当天移除
  localDate: string; // YYYY-MM-DD
}
```

现有归档接口成功后，同时删除该项目的重点偏好。主题继续使用浏览器本地存储，不进入服务端数据库，因为页面必须在接口返回前确定主题。

## 11. 数据流

1. 现有项目接口返回项目列表。
2. 页面读取重点偏好。
3. `FocusSelector` 先放置有效的手动置顶项目。
4. `FocusSelector` 按固定规则补足到三个。
5. “今日”页面展示重点卡和推荐原因。
6. 用户调整重点时，只更新偏好，然后重新运行同一个纯函数。
7. 项目数据刷新时，偏好保持不变，自动位置根据新数据重新计算。

该流程不会因为打开首页而新增 AI 调用。

## 12. 加载、空态与错误

- 首次加载：显示三个与最终卡片尺寸一致的骨架，不显示全屏转圈。
- 刷新中：保留上一次可用内容，只更新顶部状态。
- 部分来源失败：显示一条紧凑提示，并继续使用其他来源。
- 全部项目为空：说明需要先在 Claude Code 或 Codex 中产生项目，再提供刷新操作。
- 重点少于三个：显示空位置和“从项目中选择”，不重复同一个项目补位。
- 偏好保存失败：保留页面当前操作结果并提示重试；刷新后以服务端已保存状态为准。
- 详情加载失败：面板内显示错误，不关闭整个项目页面。

## 13. 响应式、动效与可读性

- 主要验收尺寸为 1366×768；标题、状态和三张重点卡必须完整出现在首屏。
- 1024 像素宽度仍保持三张重点卡并列；更窄时改为纵向排列。
- 所有页面不得产生整页横向溢出。
- 动画只用于页面内容淡入、卡片悬停和详情面板进入，时长 120–180 毫秒。
- 尊重 `prefers-reduced-motion`，关闭非必要动画。
- 不使用持续闪烁、呼吸光、渐变网格或大面积彩色阴影。
- 图标必须有文字提示或可读名称，不能只依赖颜色表达状态。

## 14. 现有代码的定向调整

- `App.tsx`：导航改为今日、项目、动态、设置；加入主题控制。
- `TriageView.tsx`：由新的 `TodayView` 取代。
- `ProjectCard.tsx`：拆分为重点卡、紧凑列表行和详情内容，不再承担所有场景。
- `KanbanView.tsx`：删除悬停放大状态，改为紧凑阶段布局。
- `FilterBar.tsx`：仅在项目页使用，并收敛为紧凑工具栏。
- `index.css`：从散落的 Tailwind 颜色类转为语义化 CSS 变量。
- `SettingsView.tsx`：增加“跟随 Windows”主题选项。
- 核心、服务端和现有项目接口保持原职责，不做无关重构。

## 15. 测试与验收

### 15.1 自动测试

`FocusSelector` 至少覆盖：

1. 三个手动置顶保持顺序；
2. 少于三个置顶时自动补位；
3. 当天移除后不再推荐；
4. 第二天移除记录失效；
5. 归档和完成项目被排除；
6. `waiting` 不抢占前两层推荐；
7. `user-action` 获得对应推荐原因；
8. 输入完全相同时输出顺序稳定；
9. 总结缺失时仍能依靠机械信号工作；
10. 可选项目少于三个时不重复项目。

偏好接口至少覆盖：

1. 最多三个且路径唯一；
2. 非法日期返回 400；
3. 重复排名不可能落库；
4. 归档会清除该项目偏好；
5. API 不影响现有设置与归档数据。

## 16. 交付边界

本设计作为一个完整界面改造交付，但实现时按以下顺序拆分：
